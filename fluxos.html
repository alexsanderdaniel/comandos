Fluxos do dia a dia

Sequências de trabalho para criar, versionar, publicar, executar e diagnosticar projetos.

⌕/
0 tópicos visíveis
Fluxo 1

Novo projeto estático → GitHub

  1. 1
    Abra o terminal na pasta do projeto.
  2. 2
    Execute git init.
  3. 3
    Execute git add ..
  4. 4
    Crie o primeiro commit.
  5. 5
    Crie um repositório vazio no GitHub.
  6. 6
    Configure origin.
  7. 7
    Faça git push -u origin main.
Fluxo 2

Alterar e enviar uma nova versão

  1. 1
    Use git status.
  2. 2
    Revise alterações com git diff.
  3. 3
    Execute git add ..
  4. 4
    Crie um commit com mensagem clara.
  5. 5
    Execute git push.
Fluxo 3

Publicar HTML/CSS/JS no GitHub Pages

  1. 1
    Envie o projeto para a branch main.
  2. 2
    No GitHub, abra Settings → Pages.
  3. 3
    Selecione Deploy from a branch.
  4. 4
    Escolha main e /(root).
  5. 5
    Aguarde a URL publicada.
Fluxo 4

Trabalhar em uma nova funcionalidade

  1. 1
    Atualize main com git pull.
  2. 2
    Crie uma branch com git switch -c nome.
  3. 3
    Faça alterações e commits.
  4. 4
    Envie com git push -u origin nome.
  5. 5
    Abra um Pull Request.
  6. 6
    Após revisar, faça o merge.
Fluxo 5

Clonar um projeto em outro computador

  1. 1
    Copie a URL do repositório.
  2. 2
    Execute git clone URL.
  3. 3
    Entre na pasta com cd projeto.
  4. 4
    Confira com git status.
Fluxo 6

Rodar um projeto PHP no XAMPP

  1. 1
    Pare serviços conflitantes se necessário.
  2. 2
    Inicie o XAMPP.
  3. 3
    Coloque o projeto em /opt/lampp/htdocs/.
  4. 4
    Acesse http://localhost/NOME/.
  5. 5
    Use phpMyAdmin se o projeto tiver banco local.
Fluxo 7

Descobrir por que o XAMPP não inicia

  1. 1
    Execute lampp status.
  2. 2
    Verifique portas 80, 443 e 3306.
  3. 3
    Teste o Apache com httpd -t.
  4. 4
    Leia o log do Apache.
  5. 5
    Leia o log do MySQL.
Fluxo 8

Antes de apagar ou desfazer

  1. 1
    Confirme onde você está com pwd.
  2. 2
    Confira arquivos com ls ou git status.
  3. 3
    Prefira operações reversíveis.
  4. 4
    Só use comandos destrutivos quando entender o impacto.
